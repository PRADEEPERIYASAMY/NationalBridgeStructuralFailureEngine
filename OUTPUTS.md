# Bridge Failure Platform — Output Interpretation Guide

All output files generated by the E2E platform pipeline are stored as compressed, schema-preserving **Apache Parquet** files under the `data/` directory.

---

## 1. Output Files Summary

| Filename | Description | Key Fields | Row Count |
| :--- | :--- | :--- | :--- |
| `data/bridge_risk_scores_2025.parquet` | Predicted risk probabilities for all operational US bridges. | `bridge_key`, `scour_risk`, `deterioration_risk`, `overload_risk`, `collision_risk`, `fire_risk` | 624,193 |
| `data/shortlist_2025.parquet` | Focused list of high-risk candidate bridges requiring structural review. | `bridge_key`, `lowest_major_rating`, `scour_flag`, `load_deficient_flag`, `adt` | 25,144 |
| `data/driver_ranking_*.parquet` | Feature importance rankings showing what structural attributes drive model risk predictions. | `feature`, `mean_abs_shap`, `failure_category` | ~20 per category |
| `data/processed/labeled_bridges.parquet` | Unified labeled database containing matched Wikipedia failures and programmatically verified anomalies. | `bridge_name`, `state`, `year_failed`, `cause`, `bridge_key` | 555 |

## 2. How to Query the Output Parquet Files

Because Parquet is a compressed columnar format, you cannot inspect it with a text editor. Use the following key methods to query the output tables:

### A. Querying via Python (Pandas)
Load the files directly into memory as standard Pandas DataFrames:
```python
import pandas as pd

# Load the shortlist
df_shortlist = pd.read_parquet("data/shortlist_2025.parquet")
print(df_shortlist.head())

# Load the risk scores
df_scores = pd.read_parquet("data/bridge_risk_scores_2025.parquet")
print(df_scores.describe())
```

### B. Querying via SQL (DuckDB Python/CLI)
Use DuckDB to run fast SQL queries directly on the Parquet files on disk without loading the entire tables into memory:
```python
import duckdb

# Join risk scores with clean NBI metadata to view the names and locations of high-risk bridges
query = """
    SELECT 
        c.facility_carried, 
        c.features_intersected, 
        c.state_code, 
        s.scour_risk
    FROM 'data/bridge_risk_scores_2025.parquet' s
    JOIN 'data/processed/bridges_clean_2025.parquet' c ON s.bridge_key = c.bridge_key
    ORDER BY s.scour_risk DESC
    LIMIT 5
"""
df_results = duckdb.query(query).df()
print(df_results)
```

## 3. How to Interpret the Scores

### A. Risk Probabilities (`bridge_risk_scores_2025.parquet`)
* The risk scores represent estimated probability values between `0.0` (0%) and `1.0` (100%).
* Because actual bridge collapses are rare in the general population, average scores will hover around 2% to 6%.
* **Extreme Risk Identification**: To isolate outliers, look at the **99.9th percentile** threshold. Bridges with scores above these limits represent extreme structural anomalies:
  * **Scour Risk Anomaly Limit**: $\ge 99.5\%$
  * **Deterioration Risk Anomaly Limit**: $\ge 99.8\%$
  * **Overload Risk Anomaly Limit**: $\ge 97.4\%$

### B. Candidate Shortlist (`shortlist_2025.parquet`)
* This is a pre-filtered **4.0% subset** of the entire inventory.
* Bridges enter this list if they have:
  1. A structural condition rating of **poor** or worse ($\le 4$).
  2. Or have an active load restriction flag (`load_deficient_flag = 1`).
  3. Or have a critical scour rating (`scour_code <= 2`).

### C. Driver Rankings (`driver_ranking_*.parquet`)
* Ranked using **SHAP (Shapley Additive exPlanations)** values.
* The higher the `mean_abs_shap` value, the more critical that physical factor is in driving model predictions.
* For example, the `scour` model is primarily driven by `scour_code` (Item 113) and `reconstruction_age` (rehabilitation recency).
